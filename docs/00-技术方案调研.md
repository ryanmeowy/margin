# OpenDesign 订阅用量 · macOS (arm64) App — 技术方案调研

调研对象：`/Users/ryan/Downloads/index.html`（CoRouter 原型，2859 行，纯 HTML/CSS/JS）
目标：原生 macOS 菜单栏 App，1:1 复刻原型，展示 OpenDesign 订阅用量。
环境事实：macOS 15.7.7 / arm64 / 只有 Command Line Tools（**没有 Xcode**）/ swiftc 6.1.2 / 仅 ad-hoc 签名。

---

## 0. TL;DR

| 决策 | 结论 |
|---|---|
| UI 技术栈 | **AppKit 外壳 + WKWebView 复用原型 HTML/CSS**（不是 SwiftUI 重写） |
| 面板实现 | **自定义 NSPanel + NSVisualEffectView(.popover, behindWindow) + maskImage 画圆角与箭头**，不用 NSPopover（形状/箭头不可定制） |
| 面板底色 | 品牌底色 **78% 不透明**压在系统材质上（实测 95% ≈ 不透明、看不出材质；78% 才有浮在桌面上的透感） |
| 菜单栏 | `NSStatusItem`（template 环形图标 + 等宽数字 "96%"），右击 NSMenu |
| 设置窗口 | 真 `NSWindow`（transparent titlebar + fullSizeContentView），内容仍由同一个 WebView 渲染 |
| 数据 | 官方内部 API + 浏览器会话 Cookie（内嵌登录窗口抓取，Keychain 存储），详见 `03-data-api.md` |
| 构建 | `swiftc` 直接编译 + 手工拼 `.app` + `codesign -s -`，**不需要 Xcode**；一条 `make` 打包（已实测：2.1s，产物 236KB，`open` 84ms 起） |
| 交付物 | `OpenDesignUsage.app`（arm64，约 3–6 MB，常驻内存 ~80–120 MB） |
| 工期 | 4–5 人日（AI 辅助下 1.5–2 天可到可验收状态） |

**为什么不把 SwiftUI 重写当首选**：原型的 UI 就是 HTML/CSS，1:1 是硬指标。SwiftUI 重写等于把同一份设计做第二遍，每个圆角、每个 `0.5px` 描边、每个 `cubic-bezier(0.22,1,0.36,1)` 都要人工再对一遍，**必然**有偏差且回归成本高。WKWebView 直接把原型当实现用，像素差 = 0。原生壳负责"像 macOS 的一部分"：菜单栏、vibrancy、窗口、键盘、通知、自启。

## 1. 原型拆解 → 原生映射

| 原型里的东西 | 原生处置 | 说明 |
|---|---|---|
| 弹出面板 `.popover`（392 宽，26 圆角，顶部小箭头） | **保留**，作为 NSPanel 内容 | 尺寸、圆角、箭头全部由 CSS 决定，mask 负责外形 |
| 概览页 / 用量明细页 | 保留 | 页间切换沿用原型的 hidden + 动画 |
| `.plan-card` 深绿渐变卡 | 保留 | 纯 CSS，不依赖材质 |
| 环形图 / 柱状图（SVG） | 保留 | 动画由 CSS 完成，无需重写 |
| 设置窗口（792×632，侧栏 196，四页） | **真 NSWindow**，内部同一份 WebView | 假红绿灯删除，用系统红绿灯；标题栏透明叠在 46pt 头部上 |
| `.wallpaper` / 假 menubar（苹果标、文件/编辑/显示/窗口/帮助、wifi、电池、时钟） | **删除** | 真实系统菜单栏已存在，不重绘 |
| 应用下拉菜单 `.app-menu` | 映射为 **NSMenu**（状态项右键 + 设置窗口激活时的应用菜单） | 命令与快捷键保留：设置 ⌘, / 刷新 ⌘R / 退出 ⌘Q / 关于 |
| 退出层 `.quit-layer`（"CoRouter 已退出 / 重新启动"） | 删除，改为真的 `NSApp.terminate` | 这是原型用来演示退出态的假界面 |
| `toast` | 保留（WebView 内），另在系统通知可用时补一条 | |
| 响应式断点（520/720/860px） | 删除 | 原生窗口固定/最小尺寸，不需要移动端布局 |
| `localStorage` 偏好 | 迁移到 `UserDefaults`（WebView 只做渲染，不持久化偏好） | 避免两套真相 |

完整规格（变量表、尺寸、状态机、动画参数、字段映射）由同事整理在 `01-prototype-spec.md`。

## 2. 选型对比

| 维度 | A. SwiftUI 纯原生重写 | **B. AppKit 壳 + WKWebView（推荐）** | C. Tauri v2 | D. Electron |
|---|---|---|---|---|
| 1:1 保真 | 中（逐像素对，易漂移） | **极高（同一份 CSS）** | 极高 | 极高 |
| 代码量 | ~2500 行 Swift | **~700 行 Swift + 原型 CSS（几乎不改）** | ~900 行混合 | ~900 行混合 |
| 冷启动 | ~0.2s | ~0.4s | ~0.6s | ~1.2s |
| 常驻内存 | 25–40 MB | **70–120 MB**（WebKit 进程） | 90–140 MB | 180–260 MB |
| 包体 | ~2 MB | **~4 MB**（系统 WebKit，不打包内核） | 8–15 MB（Rust） | 80–120 MB |
| 动画还原 | 需手写 spring/时序 | **CSS 原样**（cubic-bezier 一致） | 原样 | 原样 |
| 迭代速度 | 慢（改样式要重编译） | **快（改 CSS 直接刷新）** | 快 | 快 |
| 系统集成 | 最好 | 好（AppKit 全可用） | 中 | 中 |
| 无障碍 | 最好 | 中（WebView 语义） | 中 | 中 |
| 本机分发 | 简单 | **简单（ad-hoc）** | 需 Rust 工具链 | 巨大 |
| 主要风险 | 视觉对不上、返工 | WebKit 透明/材质叠加细节 | 引入 Rust 工具链 | 体积/内存 |

**取舍结论**：这是一个"小而美的展示型面板"，瓶颈在视觉保真和迭代速度，不在 CPU。选 B。
预留退路：数据层（`UsageStore`）、动作层与视图完全解耦，将来若要"真原生"，只换 View 层，其余不动。

### Swift ↔ JS 桥

| 方向 | 机制 | 载荷 |
|---|---|---|
| Swift → Web | `webView.evaluateJavaScript("od.applyState(\(json))")` | 一次性完整状态（见 `03` 第 4 节映射） |
| Web → Swift | `window.webkit.messageHandlers.bridge.postMessage({type:"refresh"})` | `refresh` / `openSettings` / `close` / `exportCSV` / `relogin` / `setPref` |
| 高度 | Swift 注入 `document.querySelector('.popover').getBoundingClientRect()` 或首次 resize 后回报 | 面板高度 = min(内容高, 屏高-80) |
| 主题 | Swift 监听 `AppleInterfaceThemeChangedNotification`，注入 `document.documentElement.dataset.theme` | system/light/dark 三态 |

**状态单一真相在 Swift**：Web 只渲染。原型的 `prefs/localStorage` 逻辑全部移到 `Prefs.swift`（UserDefaults），页面里那套 IIFE 换成 `bridge.js`（约 150 行：applyState、切换视图、触发动作、绘制图表）。

## 4. 关键技术点与风险

| # | 点 | 做法 | 状态 |
|---|---|---|---|
| 1 | 状态项图标 | 代码绘制 16×16 环形（track 28% alpha + arc 实心），`isTemplate = true`，随菜单栏亮暗自动反色；文字用 `NSFont.monospacedDigitSystemFont` | 可编译；颜色牺牲（R4） |
| 2 | 透明 WebView | **只能靠 KVC** `setValue(false, forKey:"drawsBackground")`；`underPageBackgroundColor` 单独无效（圆角外 alpha 仍 255）；HTML/body 必须透明 | ✅ 实测通过，带 responds 兜底（R9） |
| 3 | 面板外形 | NSVisualEffectView `maskImage`：26pt 圆角矩形 + 顶部菱形（原型 14×14 转 45°，可见底宽 19.8 / 高 9.9）；`blendingMode = .behindWindow`；`state = .active` | ✅ 轮廓实测一致；`maskImage` 不裁子视图，底色层要自绘（`TintView`） |
| 4 | 面板定位 | 取状态项按钮的屏幕坐标 → 居中于按钮、clamp 到屏幕、空间不足翻到上方 | 方案确定 |
| 5 | 获得焦点/输入 | NSPanel 子类 `canBecomeKey = true`；打开时 `NSApp.activate(ignoringOtherApps: true)`；关闭后把焦点还给原 App | 方案确定（细节 spike 验证） |
| 6 | 点击外部关闭 | `NSEvent.addGlobalMonitorForEvents(matching: .leftMouseDown/.rightMouseDown)` + 本地 monitor；全局鼠标监听**不需要**辅助功能授权 | 方案确定 |
| 7 | ESC / ⌘R / ⌘, | 面板为 key window 时的本地 `keyDown`；设置窗口走 NSMenu 快捷键 | 方案确定 |
| 8 | 双材质叠加 | WebView 内 `.popover` 的 `backdrop-filter` 必须去掉（否则在 vibrancy 上二次糊）；`--panel` 透明度下调到 ~0.72 让材质透出 | spike 验证中（R3） |
| 9 | 设置窗口 | `styleMask [.titled,.closable,.miniaturizable,.resizable,.fullSizeContentView]`，`titlebarAppearsTransparent = true`，`title = "设置"`；46pt 头部作为拖拽区（`-webkit-app-region: drag` 等价 → WebView 里用 `mouseDownCanMoveWindow`） | 方案确定（R5） |
| 10 | 登录 | 独立窗口加载 `open-design.ai/cloud/login`，登录成功后从 `WKWebsiteDataStore.default().httpCookieStore` 取 `__Secure-better-auth.session_token`，存 Keychain；支持"粘贴 Cookie"兜底 | 方案确定 |
| 11 | 通知 | `UNUserNotificationCenter`；ad-hoc 签名下可能拿不到授权（见 R1），降级为面板内提示 | 风险已知 |
| 12 | 登录时自启 | `SMAppService.mainApp.register()`（macOS 13+），失败时静默降级并在设置页显示"需将 App 移入 /Applications" | 风险已知 |
| 13 | CSV 导出 | `NSSavePanel` + UTF-8 BOM；列头沿用原型 | 方案确定 |
| 14 | 无 Xcode 构建 | `swiftc -O Sources/*.swift -o App.app/Contents/MacOS/App`，手写 Info.plist，`codesign --force --sign -`；已验证 AppKit+WebKit 能编译 | **已编译验证** |

## 8. 风险清单

| ID | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | ad-hoc 签名下 `UNUserNotificationCenter` 可能授权失败；`SMAppService` 自启可能注册失败 | 通知/自启不可用 | 降级为面板内提示；设置页显示真实状态而不是假开关；需要时引导移入 /Applications |
| R2 | 官方接口未公开，可能改字段 | 数据页空白 | 解析层"未知字段忽略、缺失即降级"；版本号随请求发送；401/403/429 分开处理 |
| R3 | `backdrop-filter` 与 vibrancy 叠加 | 无（实测空转） | 已实测：透明 WebView 里开/关逐像素相同，直接删。真正的取舍是 95% 底色≈不透明 vs 78% 才有透感 |
| R4 | 菜单栏图标只能是模板色（黑白），原型的薄荷绿弧线保不住 | 视觉小差异 | 模板图更"像系统"；如需保留绿色可用非模板图（不随主题反色，需实测） |
| R5 | WebView 里拖不动窗口 | 设置窗口无法移动 | 用 `NSWindow.isMovableByWindowBackground` + 顶部区域放 NSView 覆盖层拦截拖拽 |
| R6 | 登录 Cookie 有过期时间（观察值约 1 年） | 突然 401 | 401 时顶部横幅"登录已过期 · 重新登录" |
| R7 | 面板高度随内容变（概览 638 / 明细更长） | 跳动 | 只在视图切换时重算高度并做 120ms 动画 |
| R8 | 采集到的真实响应字段与文档假设不符 | 映射错 | M3 第一步先抓一次真实响应存 `fixtures/captured/`，再定 schema |
| R9 | 透明 WebView 依赖私有 KVC `drawsBackground` | 系统升级/上架风险 | `responds(to:)` 探测，失败退回不透明面板（CSS 自绘底色），功能不受影响 |
| R10 | 自定义面板拿不到系统投影（实测边缘 36pt 内像素恒定） | 观感偏平 | 先试 `window.invalidateShadow()`；仍无则 host view `layer.shadowPath` 自绘（同一条 shapePath） |
| R11 | 多屏：`NSScreen.main` ≠ 状态项所在屏 | 面板弹到另一块屏 | 用 `statusItem.button?.window?.screen`，x 按 caret 反推并 clamp 到 `visibleFrame` |
| R12 | 本机是深色模式，浅色模式未实机截图 | 浅色下发灰/白块 | M5 强制 `NSApp.appearance = NSAppearance(named: .aqua)` 跑一遍全页面截图 |

## 10. spike 实测回填（02-native-spike.md 摘要）

| 问题 | 实测结论 |
|---|---|
| 透明 WebView | 成立，但**只有** KVC `setValue(false, forKey:"drawsBackground")` 有效；`underPageBackgroundColor = .clear` 单独时圆角外 alpha 仍 255；HTML/body 必须透明 |
| 26pt 圆角 + 箭头 | 轮廓完全对得上（箭头可见底宽 19.8 / 高 9.9）；`maskImage` **不裁剪子视图**，底色层必须自绘（`TintView` 用同一条 path） |
| 系统投影 | **没拿到**：垫底窗口上沿面板左边缘外扫 36pt 像素恒定。需 `invalidateShadow()` 或自绘 `layer.shadowPath` |
| 面板行为 | 成立：`isKeyWindow=true`、firstResponder 是 WKWebView、真键盘输入进 DOM、前台应用仍是 Chrome、ESC 关、点外面 close、面板顶贴 `visibleFrame.maxY`、边缘 clamp 不歪箭头 |
| backdrop-filter | 空转（开/关逐像素相同），建议删除 |
| 打包 | CLT 手工 `.app` + ad-hoc 可用：构建 2.1s、产物 236KB、`open` 84ms、菜单栏图标正常、RSS ≈105MB |
| 高度信号 | `getBoundingClientRect().height + 10` 配 `setTimeout(60ms)`；**不能用 rAF**（离屏 WKWebView 被节流，面板永远不出现）；原生 `didFinish` 再量一次兜底 |
| 尺寸基准 | 概览页内容高 **693pt**（+箭头 10 = 703），面板宽 392 |

### 由此确定的三条实现约束

1. 面板底色与圆角/箭头**只在 Swift 一处定义**（`shapePath` + `TintView`），CSS 不再画圆角、箭头和投影，避免两套几何打架；CSS 的 `--panel` 只作为取色来源（`getComputedStyle` 读一次）。
2. 面板高度由页面报数驱动，超出 720 交给 `.pop-body` 内部滚动；视图切换后重报一次。
3. 关面板只认 `didResignKey`（点桌面、点别的 App 都会触发），ESC 额外挂 local keyDown；不依赖全局鼠标监听。

## 11. 实现回填（写码之后）

| 决策 | 结果 | 原因 |
|---|---|---|
| 会话 token 存哪 | **文件**（Application Support，0600），不再用 Keychain | ad-hoc 签名每次重编都换身份，Keychain 读一次弹一次授权框；文件方案对个人工具足够，且可一键迁移/删除 |
| 面板高度 | 概览 **705pt**（不是 693） | 693 来自 spike 页误命中原型 520px 紧凑断点；删掉断点后 1:1 高度是 705 |
| 明细页超屏 | 原生把面板钉在 760pt，页面切 constrained：头/尾固定、只滚内容区 | 否则整页滚动会把头部和页脚一起滚走 |
| 7 天柱状图 | 真实翻页聚合（limit=100、250ms 间隔），**与 15 分钟配额刷新解耦**：点开面板/每 2 小时只重算今天（1–5 请求），跨天或 >24h 才全量（~24 请求） | 服务端没有按日聚合接口；全量每次 24 请求既慢又容易 503，而只有「今天」在变 |
| 登录 | 内嵌 WKWebView 登录窗抓 __Secure-better-auth.session_token + 设置页可粘贴 Cookie | 两套入口覆盖自动/手动 |
| 状态项百分比 | 取最短窗口（5h 优先，没有则 7d），模板图标随菜单栏明暗反色 | 与原型一致 |
| 面板打开的刷新 | 60 秒节流；后台刷新不显示「正在同步…」，只有手动刷新显示 | 三个端点各 ~0.9–1.1s，每次点开都转圈会显得很慢 |
| 开发参数 | --mock / --show / --settings / --toggle / --eval / --seed-token-file | 截图与免登录验收 |

### 12.1 登录入口修正（2026-11-06 下午）

- 症状：点「用浏览器登录」出现 404。
- 原因：登录页在 `open-design.ai`，而代码用 API base `amr-api.open-design.ai` 拼了 `/cloud/login`。
- 修复：`LoginWindowController.webBase(for:)` 去掉 `amr-api.` / `api.` 前缀得到站点根，再拼 `/cloud/login`。
- 顺手加了一道校验：抓到 `__Secure-better-auth.session_token` 后先 `OpenDesignAPI.validate`，有效才写 Keychain/文件并关窗，避免把无效会话存进去。
### 12.2 登录改为系统浏览器 + 会话同步（2026-11-06 下午）

- 需求：不要内联浏览器，用系统默认浏览器登录。
- 约束：计费接口只认浏览器会话 Cookie；系统浏览器的 Cookie 我们读不到，除非走钥匙串/全盘访问授权。
- 方案：「用浏览器登录」打开默认浏览器 → 回到 App 时用 `BrowserSessionImport` 从 Chrome/Edge/Brave 同步：
  复制 `Local State` + `Cookies` 到临时目录 → 起一个隐藏的 headless 浏览器（独立 user-data-dir）→ CDP `Storage.getCookies` → 结束进程并删临时目录。
- 不碰钥匙串、不需要辅助功能/全盘访问权限；只取 `__Secure-better-auth.session_token`，且先调 API 校验。
- 内置 WebView 登录保留为兜底（`embeddedLogin`），界面上不再作为默认入口。
- 顺带修：登录页 404（`amr-api.` 前缀）、多屏下设置窗口恢复成屏幕外或被其他 App 压住（on-screen 校正 + `.floating`）。
### 12.3 用量明细页抖动（2026-11-06 下午）

- 现象：切到「用量明细」后整个面板持续小幅跳动。
- 实测：窗口尺寸稳定（40 帧采样无变化），抖动来自高度上报与约束开关在阈值上反复翻转：
  - 明细内容 781pt > 上限 760 → 原生进入 constrained；
  - 页面在 constrained 下用 `.popover.scrollHeight` 量到的是「视口高」760 → 原生判断 760 不超上限 → 解除约束；
  - 解除后又量回 781 → 再次约束……约 10Hz 循环。
- 修复两处：
  1. 页面在 constrained 下改为「头 + 内容区 scrollHeight + 脚 + 10」量内容高，稳定报 781；
  2. 原生加 12pt 死区：已在约束态时要低于 760-12 才解除。
- 复测：高度上报只剩 706 / 781 两个值，面板稳定停在 760。
### 12.4 菜单栏图标对齐（2026-11-06 下午）

- 之前：状态项用 **template image**（黑图 + alpha，系统自动反色）→ 菜单栏里永远是白色/灰色，和原型的陶土色环对不上；尺寸也是 16pt / 线宽 2.0。
- 现在：按原型 18×18 的几何（r 6.3、线宽 2.1、中心点 1.25）用陶土色 `#E08A6D` 直接绘制，`isTemplate = false`；文字改用 semibold 600，去掉手写的细空格（用系统图字间距）。
- 验证：在外接屏活动菜单栏里是陶土色环 + 100%。
- 有意保留的两处差异：① 不上模拟图里那层圆角底 pill（真实菜单栏项本身是透明底，加底会像常驻按下态）；② 非模板图不随菜单栏明暗反色，浅色菜单栏里仍是陶土色（对比度足够）。
### 12.5 价格改由官方接口提供（2026-11-06 下午）

- 问题：之前用的是本地价目表（go 月 7 / 年 84），实际 go 月付是 **$10**，7 是年付折算的月价——数字是错的。
- 官方接口：`GET /api/v1/billing/subscription/offers` 返回每个档位 × 周期的报价：
  `{ membershipTier, billingInterval(monthly|yearly), originalPriceUsd, finalPriceUsd, … }`；
  实测 go 月付 `finalPriceUsd: "10.00"`、年付 `"84.00"`，plus 月付 `"20.00"`。
- 计费周期仍来自 `snapshot.plan.interval`（`month` / `year`），不再猜。
- 规则：按「档位 + 周期」匹配 offer → 用 `finalPriceUsd`（含折扣）；匹配不到（团队按席位计价、接口失败）→ **整行价格隐藏**，只显示套餐名 / 生效状态 / 到期日。
- 页面：`#planPrice` 为空时 `hidden=true`，不会留下一个孤零零的「/ 月」。

### 12.7 登录反馈 / 退出登录 / 「正在同步」卡死（2026-11-06 下午）

- 反馈：点「用浏览器登录」后，设置页提示「已在新标签页打开登录页，登录完成后点『从 Chrome 同步』」；回到 App 会自动同步，成功后在按钮上方显示「已从浏览器同步，会话验证通过」，失败显示红色原因并弹一次窗。
- 新增「退出登录」：删本机会话文件、清 WKWebView Cookie、清内存与 cache.json、状态项回到占位图标、面板回到「尚未配置登录会话」。入口：设置页按钮 / 菜单栏右键。
- 修一个连带 bug：`UsageStore.refresh` 之前在 `defer { refreshing = false }` 之前就 emit，导致最后一次状态永远带 busy=true——界面上会一直停在「正在同步…」。现在 defer 里补一次 emit，busy 正常落回 false。
- 设置页的「上次验证」也不再显示忙碌文案（busy 时退回上一次的稳定文案）。
### 12.8 登录一步化 / 高级设置收纳（2026-11-06 下午）

- 为什么要「点两次」：浏览器和 App 的 Cookie 是两套仓库，App 读不到浏览器里的会话，除非走钥匙串授权或临时复制 profile 起一个隐藏浏览器。没有服务端回调可注册，所以没法天然一步。
- 现在做成一步：点「用浏览器登录」后，App 每 2 秒看一眼浏览器 Cookie 库的修改时间（最多 5 分钟），一旦登录写入了 Cookie 就自动导入 + 校验；如果本来就已经登录，2 秒后直接同步。用户只需点一次。
- 账户页重排：默认只看到「连接状态 + 用浏览器登录 / 从 Chrome 同步 / 退出登录」；服务地址、账号、会话 Cookie、保存并验证收进「高级设置」折叠。
- 术语澄清：「访问令牌」改名「会话 Cookie」，说明里写明不是 API Key——计费接口只认浏览器会话 Cookie。
- 退出登录时会取消等待中的自动同步，避免刚退出又被自动登回去。
### 12.9 简化账户页（2026-11-06 晚）

- 未登录时侧栏不再显示「异常」：按连接状态显示 正常 / 登录已过期 / 无权限 / 离线 / 未登录。
- 「高级设置」（服务地址 / 账号 / 会话 Cookie / 保存并验证）与「从 Chrome 同步」按钮全部隐藏，第一版只保留：浏览器登录 → 自动同步 → 拉取订阅信息。
- 点「用浏览器登录」后按钮进入「等待登录…」禁用态，页面上提示「已在浏览器打开登录页，登录完成后会自动同步…」；拿到 Cookie 并校验通过后提示「登录成功」；5 分钟内没检测到则提示「没有检测到浏览器登录，可以再试一次」。
- 修一个竞态：退出登录时若有刷新在途，旧响应会把状态写回「已连接」。`UsageStore` 增加 generation，reset 后丢弃在途结果。
### 12.10 登录等待逻辑修正（2026-11-06 晚）

- **Bug**：点「用浏览器登录」后第 2 秒会先试一次导入；用户当然还没登完，这次静默失败把 `authPending` 清成 false，loading 直接消失。等于没给用户登录时间。
- **Bug**：Cookie 变更检测只看 `Default/Cookies`，漏了 `Cookies-journal` 和 `Profile 2/3`（本机有 3 个 Chrome profile），真实的登录写入可能完全检测不到。
- **修法**：
  1. 静默失败不再改 `authPending`——只有成功、超时（10 分钟）、取消（退出登录/关进程）才结束 loading；
  2. 指纹覆盖所有 Chromium 系浏览器的所有 profile，`Cookies` + `Cookies-journal` + `Network/Cookies`；
  3. 每 2 秒比对指纹，变了就导入；另外每 20 秒兜底强试一次；
  4. 面板顶部的连接条在等待期间显示「等待浏览器登录…」。
- 验证：模拟登录 30 秒内发生 3 次失败导入，`pending` 始终为 true，loading 不消失。
### 12.11 Review 后的第一批修复（2026-11-06 晚）

**1. 删掉重复的设置状态（单一来源）**
